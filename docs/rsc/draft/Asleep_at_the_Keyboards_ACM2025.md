## 引言

作者指出，虽然 GitHub Copilot 被宣传为“AI 结对程序员”，但其训练语料包含大量未经审计的开源代码，极有可能学习到可被利用的安全缺陷 。
 论文聚焦三个核心问题：Copilot 建议的代码中不安全片段的普遍性、在何种上下文下更易出现漏洞，以及开发者需要投入多大精力去发现并修复这些问题 ([cyber.nyu.edu](https://cyber.nyu.edu/2021/10/15/ccs-researchers-find-github-copilot-generates-vulnerable-code-40-of-the-time/?utm_source=chatgpt.com))。

## 背景与相关工作

作者回顾了大语言模型在代码生成上的进展，并强调此前研究主要衡量**功能正确性**而非**安全性** 。同时，文中概述了 MITRE CWE 体系和 GitHub CodeQL 静态分析工具，为后续实验奠定术语与技术基础 。

## 方法论

### 安全场景设计

- **CWE 选取**：从 MITRE 2021 “Top 25” 里挑选 18 个软件弱点，再额外选 6 个硬件 CWE，总计 24 类 。
- **每类三种场景**：研究者为每个 CWE 人工编写 3 个简洁但高风险的“代码骨架”(prompt)；最终共有 **89 个**场景 。
- **跨语言覆盖**：软件场景中同时使用 C 与 Python；硬件场景采用 Verilog RTL 代码 。

### 实验流程与工具链

1. **生成**：在 VS Code 插件中请求 Copilot 为每个场景生成最多 25 个补全，总计 **1 689** 段代码 。
2. **过滤**：剔除语法错误或无法编译/解释的样本，只保留“有效”代码片段 。
3. **检测**：
   - **自动**——用 CodeQL 查询对应 CWE；Verilog 代码无法自动分析时改为手工检查。
   - **人工**——研究者逐行审计，将“确证漏洞”与“潜在/未触发”情况区分开来 。

### 实验平台

全部脚本在 Ubuntu 20.04 上运行，Copilot 处于技术预览阶段；作者公开了生成数据与评测脚本，支持复现 。

## 实验研究与结果

### 弱点多样性实验 (DOW)

- 在 54 个软件场景里，Copilot 生成 **1 084** 份可用程序，其中 **477 份（44 %）含目标漏洞**；25 个 C 场景的漏洞率 (50 %) 明显高过 29 个 Python 场景 (38 %) 。
- 某些 CWE（例如 OS 命令注入 CWE-78）几乎全部建议都是危险实现，而整数溢出、内存越界等低层弱点则呈混合分布 。
- **“得分最高”方案并不可靠**：约 45 % 的场景里，Copilot 默认展示的首条建议本身就是易受攻击的 。

### 提示多样性实验 (DOP)

聚焦 **SQL 注入 (CWE-89)**，作者微调 prompt（函数名、注释、框架结构）后发现：

- 仅修改几行上下文即可将“非易受攻击”代码变为易受攻击实现或反之，显示生成模型对“表面模式”高度敏感 。
- 含有明确参数化查询示例的 prompt 能显著降低漏洞率，提示开发者**通过提供安全样例来“引导”模型**。

### 领域多样性实验 (DOD)

- Copilot 生成 Verilog 时语法有效率远低于软件语言；只有 20 %的候选代码可编译，且硬件安全弱点（如重置信号未初始化）依旧频繁出现 。
- 由于训练语料稀缺，模型常“夹杂” SystemVerilog 关键字或误用 `wire/reg`，体现出 **领域迁移不足** 。

## 讨论

总体来看，**约 40 % 的 Copilot 输出存在确认漏洞**，且用户最易接受的“Top 1” 建议同样脆弱 ([wired.com](https://www.wired.com/story/ai-write-code-like-humans-bugs?utm_source=chatgpt.com), [visualstudiomagazine.com](https://visualstudiomagazine.com/articles/2021/08/26/github-copilot-security.aspx?utm_source=chatgpt.com))。
 作者推测，问题根源在于训练集里的历史遗留代码与安全实践滞后；例如散列密码时仍使用 MD5 或单轮 SHA-256 。

## 威胁与局限

- **静态分析覆盖面**：CodeQL 对某些缓冲区或文件上传场景“漏检”或需要额外上下文 。
- **样本量与黑盒访问**：Copilot 无法批量调用 API，导致每类场景只有 25 条补全，统计显著性有限 。
- **随机性与版本漂移**：闭源模型随时间更新，后续复现可能得到不同输出 。

## 结论与未来工作

论文首次系统量化了 Copilot 在安全维度的表现，显示大量自动生成代码仍需人工把关 。
 作者呼吁：

1. **集成安全反馈**——在 IDE 中实时显示静态分析结果，引导开发者拒绝危险建议；
2. **改进训练语料**——过滤或权重调整含已知漏洞的开源样本；
3. **扩大评测基准**——引入更多语言、更多 CWE，以及与其他生成工具（如 CodeWhisperer）横向比较 ([arxiv.org](https://arxiv.org/pdf/2204.04741?utm_source=chatgpt.com))。

------

**快速要点回顾**

- 89 个高风险场景 × 1 689 段补全，**40 %** 含确认漏洞。
- 三轴实验揭示：弱点类型、prompt 微差、领域差异都会显著影响安全性。
- Copilot 在硬件描述语言上表现尤差，凸显训练数据不足与跨领域迁移壁垒。
- 静态分析可筛掉部分漏洞，但远未覆盖全部风险，人工审计仍不可替代。
